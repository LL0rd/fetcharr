# Fetcharr Phasen 2–6 — Arbeitsplan

> Kompakter als Phase 1: pro Phase Task-Baskets für parallele Agents. Verbindlich bleiben die Spec (`docs/superpowers/specs/2026-08-19-fetcharr-design.md`) und das Mockup (`docs/design/Fetcharr.dc.html`). Konventionen aus dem Phase-1-Plan gelten weiter (TDD für Logik, .ts-Import-Endungen, keine AI-Hinweise in Commits, Dateien < ~300 Zeilen, env-Pfade).

**Ablauf je Phase:** Orchestrator erweitert Schema + installiert Dependencies (ein Commit) → parallele Agents implementieren Baskets → Orchestrator prüft (Tests, Stichproben, ggf. E2E) → Nachbesserungen → nächste Phase.

---

## Phase 2 — Library & Player

Schema-Erweiterung (Orchestrator): `files` + `resume_position_sec`, Index auf (type, created_at); Migration.

**Basket A — Files-API (web/server):** `GET /api/files` (Suche über title/uploader, Filter type/favorite, Sortierung date/title/size, Pagination), `GET /api/files/:uid`, `DELETE /api/files/:uid` (Datei + Sidecars + DB; Query-Flag `blacklist` reserviert für Phase 3), `POST /api/files/:uid/favorite`, `POST /api/files/:uid/view` (View-Count + resume position), `GET /api/stream/:uid` (Range-Requests, korrekte Content-Type/206), `POST /api/files/zip` (mehrere uids → ZIP-Stream via archiver), `GET /api/thumbnail/:uid`. Tests auf Handler-Ebene inkl. Range-Header-Fällen.

**Basket B — Library-UI + Player (web/app):** `pages/library.vue` nach Mockup (Grid default/List, Suche, Filter All/Video/Audio/Favs, Sort Date/Title/Size, Favoriten-Stern, Dauer-Badge, Mehrfachauswahl → ZIP-Download, Delete mit Confirm-Dialog), `pages/watch/[uid].vue` (HTML5-Player über `/api/stream`, merkt resume-position via `/view`-Endpoint, Metadaten-Anzeige, Zurück zur Library). Thumbnails über `/api/thumbnail/:uid`.

**Basket C — Medienserver-Writer (worker):** NFO-Generator (Jellyfin/Kodi `<movie>`-Schema aus Info-JSON, neben die Mediendatei), Thumbnail-Konvertierung nach jpg wenn webp (ffmpeg), Crop-Ausführung nach Download wenn `cropStart/cropEnd` gesetzt (ffmpeg -ss/-to, Re-Container ohne Re-Encode wo möglich), Schreiben gesteuert über settings-Keys `write_nfo`/`write_thumbnails` (Default an). TDD mit ffmpeg-Stub.

## Phase 3 — Subscriptions & Archiv

Schema (Orchestrator): `subscriptions` (Felder laut Spec inkl. paused, cron, timerange, titleRegex, maxQuality, type, customArgs, customOutput, sponsorblock, recordLivestreams, redownloadFreshUploads, lastCheckAt, checking), `archive` (extractor, mediaId, type, subId?, title, createdAt, UNIQUE(extractor, mediaId, subId)), `files.sub_id`; jobs.sub_id. Dependencies: croner, feed.

**Basket A — Worker: Scheduler + Check-Flow:** croner-Jobs aus subscriptions-Tabelle (Reload bei Änderung via updated_at-Poll), Check: `yt-dlp -J --flat-playlist` → Einträge gegen `archive` diffen → Filter (titleRegex, timerange) → Jobs mit priority=2 + subId anlegen; nach erfolgreichem Download Archiv-Insert + files.subId; `checking`-Flag + Abbruch; redownload_fresh_uploads gemäß Spec; Livestream-Flag → `--live-from-start`.

**Basket B — Subscriptions-API + UI:** CRUD `/api/subscriptions` (+ `POST /:id/check` triggert Worker über DB-Flag `check_requested`, `POST /:id/pause`), UI `pages/subscriptions.vue` nach Mockup (Tabelle, Add/Edit-Dialog mit allen Feldern, paused/RSS-Tags, Check now, Countdown „next check"), Zod-Validierung (Cron validieren via croner).

**Basket C — Archiv + Podcast-RSS:** `/api/archive` (list/search, delete Eintrag, Import archive.txt-Upload, Export als text), UI-Seite `pages/archive.vue` (Nav-Eintrag ergänzen — Design folgt Tabellen-Muster des Mockups), `GET /api/rss/:subId?token=<apiKey>` Podcast-Feed (feed-Package, nur audio-Subs, enclosure auf `/api/stream/:uid?token=`), Token-Query-Support im Auth-Guard für stream+rss.

## Phase 4 — Tasks, Notifications, Settings, Logs

Schema (Orchestrator): `tasks`, `task_runs`, `notifications` laut Spec; jobs.not_before (Backoff).

**Basket A — Worker: Task-Engine + Tasks:** Engine (run/confirm-Zweiphasen, auto_confirm, Schedule aus tasks-Tabelle via croner, running/confirming-Flags, task_runs-Historie, Skip wenn laufend), die Tasks: backup_db (VACUUM INTO /config/backups + settings/cookies-Kopie, Rotation), missing_files_check, import_missing_files (Scan /downloads inkl. Sidecar/ffprobe), duplicate_files_check, update_ytdlp (Versionscheck/Download), delete_old_files (threshold, Ausnahmen favorites/subs), rebuild_database, import_youtubedl_material (local_db.json + Archive + users-los; Optionen: Pfad). Job-Retry-Backoff: failJob setzt not_before = min(2^attempts*30s, 15min); Claim respektiert not_before.

**Basket B — Notifications:** Worker sendet bei download_finished/download_error/subscription_found/task_confirm_needed in `notifications`-Tabelle + externe Kanäle (ntfy, Gotify, Discord-Webhook, generischer Webhook — fetch-basiert, Settings-Keys, pro Ereignistyp aktivierbar). Web: Glocken-Dropdown im Header (Mockup!) + `pages/notifications.vue`, unread-Badge via SSE (notifications in den Event-Stream aufnehmen), mark all read, `/api/notifications`-Endpoints.

**Basket C — Settings-UI + Tasks-UI + Logs:** `pages/settings.vue` nach Mockup (Tabs Downloader/Extra/API/Subscriptions/Notifications/Advanced — Notifications-Tab ergänzen; liest/schreibt `/api/settings`; API-Tab mit Key-Regenerate; Cookies-Dropzone → `/api/settings/cookies`-Upload; Restart-Hinweis wo nötig), `pages/tasks.vue` nach Mockup (Tabelle, Run now, Confirm-Button mit Zähler, Schedule-Dialog wiederkehrend/einmalig, Options-Dialog, Reset stuck tasks, DB-Restore aus Backup-Liste), Logs: Worker+Web loggen strukturiert in `<CONFIG_DIR>/logs/fetcharr.log` (einfacher JSON-Lines-Logger in shared), `/api/logs` (tail N, Level-Filter) + `pages/logs.vue`.

## Phase 5 — Storage, Metrics, Extras

Dependencies: prom-client, @vite-pwa/nuxt.

**Basket A — Storage + Metrics:** `/api/storage` (Aggregation aus files: nach uploader/subscription/type, Größen+Counts; df für Used/Free via statfs), `pages/storage.vue` nach Mockup (Stat-Kacheln, Tabs, Balken), `/metrics` (prom-client: queue-Gauges, downloads_total{status}, bytes_downloaded_total, storage per sub, ytdlp_info) ohne Auth-Zwang aber optional via Setting schützbar.

**Basket B — Bulk + Livestream + Versionscheck:** Bulk-Import-Dialog (Textarea, eine URL je Zeile → Jobs priority=1), Livestream-Erkennung in der Probe (is_live → Hinweis + `--live-from-start`-Option im Dialog), Versionscheck-Task gegen ghcr (latest-Tag-Digest vergleichen, Sidebar-Tag „new image available" via /api/version).

**Basket C — PWA + Share Target:** @vite-pwa/nuxt (Manifest, Icons aus einfachem SVG-Logo generiert, Offline-Shell), Web Share Target (`share_target` im Manifest → /share?url= öffnet Add-Download-Dialog vorausgefüllt), Bookmarklet-Snippet auf der Settings-API-Seite.

## Phase 6 — Docker, CI, Unraid

**Basket A — Container:** Multi-Stage-Dockerfile (node:22-bookworm-slim; Stage utils: ffmpeg/ffprobe static + deno wie im alten Projekt-PR — deno via GitHub-Release, arm64-Variante, armv7 skip; Stage build: pnpm install+nuxt build+worker; final: s6-overlay v3 mit services web+worker, PUID/PGID/TZ/UMASK-Entrypoint wie linuxserver-Konvention, HEALTHCHECK auf /api/health, EXPOSE 3000, VOLUME /config /downloads). Worker läuft im Container auf gebautem JS (esbuild-Bundle oder node --experimental-strip-types — Bundle bevorzugen). Lokal bauen + Smoke-Test (Container startet, Health ok, Login-Setup, ein echter Mini-Download).

**Basket B — CI + Unraid + Release-Doku:** GitHub Actions: `ci.yml` (Tests auf PR/push), `docker.yml` (push auf master + Tags: buildx amd64+arm64 → ghcr.io/<owner>/fetcharr:latest+version; zusätzlich Docker-Hub-Push NUR wenn Secrets DOCKERHUB_USERNAME/DOCKERHUB_TOKEN existieren — via `if` auf secrets); Unraid-Template `unraid/fetcharr.xml` (Repository docker.io/<user>/fetcharr, WebUI Port 3000, Pfade /config→appdata, /downloads→Share, PUID/PGID-Vars, Icon-URL auf raw.githubusercontent) + `unraid/icon.png` (aus Logo-SVG gerendert); README-Erweiterung: Docker-run/Compose-Beispiel, Unraid-Anleitung, Secrets-Setup für Docker Hub.
